# 工具箱与本地清单

本文承接 [README](../README.md)「工具箱」章的实现细节：宿主同步 await 纪律、1.5.43/1.5.44 移出工具面的版本过程、本机工具清单的完整用法（JSON 示例、字段表、异步机制、显式失败约定、代码范式与调用留痕）。

## 宿主同步 await 与工具纪律

宿主 agent loop **同步 await 一批工具**——一批没跑完，下一次模型请求就发不出去（坑 #79）。所以工具箱的纪律是：**能异步的一律异步**，同步只留给"几毫秒就能返回"的东西。

## 移出工具面的版本过程（1.5.43 / 1.5.44）

**npm 安装包里只留简单通用的能力**（1.5.43 / 1.5.44 起）：`toolkit_cmd` / `toolkit_read` / `toolkit_write` 外加两个清单管理工具 `toolbox_list` / `toolbox_reload`。`watch_read` / `mem_sync` / `pkg_stats` 三个**已从注册表移除**（不再注册、不再进 own-tools 白名单）——它们是发版方自己的特殊能力（要手表脚本目录 / 会真提交记忆仓库 / 要联网查下载量），不该进通用安装包，而且无条件注册时它们约占每轮 690 token、拉长工具面、抬高误调率。1.5.44 起改由**本机清单**（`<记忆根>/toolbox.json` → 按需注册）驱动，运行时脚本放在使用者本机（建议放家目录 `tools/` 下），不进 npm 包。

移出工具面的三个（运行时脚本搬本机，按需由清单注册）：
`watch_read`（异步手表取数）/ `mem_sync`（记忆仓库提交 + 推配置的远端）/ `pkg_stats`（npm 下载量 + 代码仓热度）。

其他工具（`mem_sync` / `pkg_stats` / `watch_read` …）**走本机清单**，脚本不进 npm 包：普通用户装插件不会看到一堆用不上的工具（1.5.42 时 6 个工具实测约 1334 token/轮）。

## 本地工具清单

清单文件：**`<记忆根>/toolbox.json`**（记忆根走 `location.json` → `AIYAYI_HOME` → 默认路径，与其它插件一致）。

```json
{
  "version": 1,
  "tools": [
    {
      "name": "mem_sync",
      "enabled": true,
      "script": "~/tools/mem_sync.js",
      "description": "同步记忆仓库：git add + commit + push 到配置的远端",
      "timeoutMs": 180000,
      "mode": "async",
      "args": [],
      "env": { "AIYAYI_MEM_PUSH_REMOTES": "origin" },
      "params": {
        "message": { "type": "string", "description": "commit message（可选）" }
      }
    }
  ]
}
```

示例里 `script` 写的是**通用建议路径**（家目录 `tools/` 下），照抄前先改成你自己机器上的实际路径。npm 包的 **`examples/`** 目录有现成的 `mem_sync.js`，直接复制到本机、在清单里把 `script` 指过去就能用（清单文件不存在属正常，想用就从零建，完整示例见 `examples/toolbox.example.json`；脚本还没复制到位时那条只会显式报"脚本不存在"不注册，不会静默吞掉）。

### 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | ✓ | 工具名，必须匹配 `^[a-z][a-z0-9_]{1,40}$` |
| `enabled` | | 默认 **false**，显式 `true` 才注册 |
| `script` | ✓ | 脚本**绝对路径**；允许 `~` 与 `%变量%` / `${变量}` 展开 |
| `description` | ✓ | 给模型的工具描述 |
| `timeoutMs` | | 默认 60000，上限 300000（超上限夹取） |
| `mode` | | **只支持 `"async"`**。写 `"sync"` 直接判这条校验失败并报回会话——同步工具会堵死整轮对话，这正是要避开的 |
| `args` | | 固定参数数组（附加在脚本路径之后） |
| `params` | | 调用参数声明（简化 JSON Schema，只支持 `string` / `number` / `boolean`；`required: true` 标必填） |
| `env` | | 给脚本的环境变量（本机配置走这里，不必改脚本） |
| `cwd` | | 脚本工作目录，默认脚本所在目录 |

### 异步机制

**每个清单工具都走异步**（`lib/toolkit-async.js` 的 `startDetachedTask`）：调用立刻返回 `{status:'started', taskId, hint}`，脚本在后台跑，跑完/超时/失败都把结果作为一条消息用 followup 推回会话。为什么走 followup 而不是 `ctx.jobs`：后者是 producer 侧能力，`preset-aiyayi` 本体没挂 `tool-jobs`；坑 #65（source 禁 undefined）/ #68（投递前让出宿主 publish 宏任务）/ #79（宿主同步 await 工具）的规避写法都收在 `lib/toolkit-async.js` 一个文件里。

脚本约定（加载器按扩展名决定解释器：`.js` → node，`.py` → python，`.ps1` → powershell，`.cmd/.bat` → cmd，其余当可执行文件）：

- **stdout 只输出一个 JSON 对象**（加载器会 `JSON.parse` 它，`hint` 字段当结论句放在投递正文最前面；不是 JSON 就原样展示）；
- 退出码非 0 或 `ok:false` → 判失败，投递正文带**退出码 + stderr 尾部摘要**；
- 环境变量里能拿到：`AIYAYI_TOOLBOX_TOOL`（工具名）、`AIYAYI_TOOLBOX_ROOT`（记忆根）、`AIYAYI_TOOLBOX_MANIFEST`（清单路径）、`AIYAYI_TOOLBOX_ARGS`（`{tool, args, fixedArgs}` 的 JSON）、以及清单里 `env` 的键。

### 显式失败约定

失败**一律显式**（不静默）：清单不存在 → 只记日志（正常，用户没配）；清单 JSON 语法错误 / 某条校验失败 / 脚本不存在 → 该条不注册，并在下一个会话的第一步注入一条 `[工具清单]` 消息说清哪条、为什么；运行失败或超时 → followup 报回退出码与 stderr 摘要。改了清单或脚本后调 `toolbox_reload` 生效。

### 代码范式（以后加长任务工具照这个写）

```js
// execute 签名必须是 (args, exec) —— exec.agent 才能 followup
[WATCH_SCHEMA, (args, exec) => executeWatchRead(args, { cfg, logUsage, warn, exec })]

// 立刻返回，run() 甩到下一轮宏任务；完成/失败/超时都投一条消息
startDetachedTask({ exec, kind: 'watch_read', hint: '已开始取数…', run: async () => ({ status, text }) })
```

调用留痕统一落 `<记忆根>/toolkit/usage.jsonl`（同步工具按次记，异步工具记 `started` + 完成两条）。

## 附：pkg_stats 的实测注意点（1.5.42 记录）

`pkg_stats` 已于 1.5.43 移出工具面，运行时脚本放使用者本机、由本地清单按需注册。以下三点写死在脚本行为里，写自己的同类脚本时用得上：

- **npm 统计的 `end` 日期滞后约 2 天**——`last-day` 不是"今天"。所以三个窗口都把 `start`/`end` 原样带回，别把这数当当日实况。
- **GitHub 直连在部分网络环境不通**（`Recv failure: Connection was reset`），兜底走第三方代理 **gh-proxy.com**——该代理会看到你查询的仓库路径（`owner/repo` 会进它的访问日志）；`github.source` 会标 `direct` / `gh-proxy`，不放心就把代理开关关掉。
- **GitCode 没有匿名 API**（`private-token` 必需，400/401），`gitcode.stars/forks` 恒为 0 且 `unavailable` 写明原因；页面上的 star 数是异步渲染的 UI 数字，不作接口确证。**Gitee 的 `watchers_count` 是"关注数"**（与 GitHub 的 watchers 语义不同）。

请求只走白名单域名（`api.npmjs.org` / `registry.npmjs.org` / `api.github.com` / `gh-proxy.com` / `gitee.com` / `gitcode.com`，精确主机名匹配），`repo`/`package` 参数做字符校验 + 逐段编码，整次调用 15 秒总预算。
