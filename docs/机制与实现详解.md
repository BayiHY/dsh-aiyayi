# 机制与实现详解

本文承接 [README](../README.md)「她是什么」能力表中六个机制行的完整细节：长期记忆、记忆路径可迁移、工具白名单、手机操控、飞书桥接、对接落到哪个会话。版本演变与「坑 #N」编号见 [更新日志](../CHANGELOG.md)。

## 长期记忆（aiyayi-memory）

自写插件 `aiyayi-memory`（本包 `lib/index.js`），两层结构：

- **核心记忆** `~\.dsh\aiyayi\memory.md`（她自规划的"每轮都想带着"的条目 + 她亲手维护的【记忆索引】目录），每轮自动注入 prompt；
- **分类档案** `~\.dsh\aiyayi\memories\` 分类树（最深三级，分类名她自己起），平时不注入、按需加载。

工具：

- `remember`（core: true/false + 分类 path）
- `recall`（全库搜：核心+整棵树）
- `memory_organize`（tree 看家底 / read 读档案 / move 挪窝 / index 重写目录 / forget 删条目——整理是她自己的家务事）
- `memory_location`（只读：记忆存在哪、怎么定下来的、有无非系统盘可搬）
- `memory_relocate`（搬家或"留在原处"，见下节「记忆路径可迁移」）

已有 memory.md 的存量条目全部视作核心，由她自己逐渐搬理。日常使用见 README「记忆路径与迁移」与完整说明 [记忆迁移完整说明](../MEMORY-MIGRATION.md)。

## 记忆路径可迁移（aiyayi-home）

自写插件 `aiyayi-home`（本包 `lib/home.js`），**唯一路径出口**：记忆路径不再散在各模块里硬拼。

- 解析优先级 = `location.json` 指路文件 > 环境变量 `AIYAYI_HOME` > 默认 `~/.dsh/aiyayi`；
- 整棵记忆（含 `presence.json`/`state.md`/`wishes.json`/`updates.json`/`memories/`）一起搬，不会半搬；
- 搬迁顺序固定为 复制 → 逐文件校验（路径集合+字节+SHA256）→ 才写指路文件 → 源目录内容改名同级 `.old` 备份；**任何一步失败即中止且源目录不动**；
- 指路根不可达时**硬失败**（记忆工具抛错、上下文每轮一条警告），绝不静默回退默认路径、绝不新建空目录顶替。

完整说明（搬迁顺序、回滚、红线、回归测试）：[记忆迁移完整说明](../MEMORY-MIGRATION.md)。

## 工具白名单（aiyayi-restrict）

自写插件 `aiyayi-restrict`（本包 `lib/restrict.js`，v3.1 pre-step 方案）+ `lib/own-tools.js` 单一真源。

- 启动期零 restrict 调用；她每个会话第一步前，先用探针从校验器报错里解析出当刻继承面全集，再 `deny = 全集 − 她自己的工具`——宿主层漏进来的 acp_*/mnemon_*/compress/search_context/working_directory 等对她隐藏，且自动适应宿主工具增减。
- 放行名单从 `own-tools.js` 读（注册处登记、放行处判定），新增工具只改一处，不再漂（见坑 #19）。
- **2026-11-02 实测生效**：新会话第 2 个请求起工具恰好 11 个，第 1 个请求仍带全套（见坑 #9）。

## 手机操控（aiyayi-phone，DSH-Go 适配）

自写插件 `aiyayi-phone`（本包 `lib/phone.js`，1.7.0，只挂本体 preset）+ `own-tools.js` 的 `'mcp__phone__'` 前缀放行。适配对象是 **dsh-app 手机版（DSH-Go）**：宿主经 `@deepseek-ai/dsh-mcp-client`（serverName: phone，stdio 走 `/opt/dsh-app/phone/relay.cjs` → App 的 phone bridge）把一族 `mcp__phone__*` 工具挂进全局工具层（screen / tap / type / scroll / key / collect / tap_xy / handoff / apps / open / intent / notify / clipboard / android_shell），**只在手机操控开启时存在**。

- **放行**：restrict 的 `deny = 继承面全集 − 她自己的工具` 会把这族收掉；`OWN_TOOL_PREFIXES` 加前缀后放行。操控没开时该族根本不在继承面上，前缀规则空转，桌面环境零副作用。
- **知情**：本体 pre-step 探测继承面（复用 restrict 的探针技巧；解析器从 `restrict.js` 导出，单一真源）。探测到手机工具 → 首轮注入完整 `[手机]` 操控守则（先读屏、编号只在本屏有效、事务走 intent、登录/验证码/支付 handoff、银行/支付/系统设置默认不碰、产出放 `/sdcard/Download/DSH-Go/`），之后每轮一行短提醒（presence 同款注入范式；压缩会吃掉首轮长段，短行每轮重注，丢不了）。探测结果按 agent 记账（WeakMap），解析失败不记账、下轮再探，绝不弄坏会话。
- **代言**：确认没有手机工具但 `/opt/dsh-app` 存在（人住在手机里）→ 每会话提一次"操控不可用，去 App 设置里开手机操控"，免得她对"看看屏幕"这种请求硬编；桌面环境（无该目录）全程静默。
- **为什么手机活本体亲手做、不派小伙伴**：强交互通道——每步返回新屏幕、元素编号只在本屏有效、敏感动作弹原生确认给他看。小伙伴在后台跑，看不见屏幕也接不住确认。worker preset 不挂 restrict，`mcp__phone__*` 会漏进它的工具面，靠 persona 新增的【手机工具不属于你】拦住（"这活得娅伊自己来"）；本体 persona【干活】的例外条款同步补了手机操控。

## 飞书桥接（aiyayi-feishu）

自写插件 `aiyayi-feishu`（本包 `lib/feishu.js`）+ 纯逻辑 `lib/feishu-logic.js`：长连接 WebSocket 接入飞书机器人（SDK `@larksuiteoapi/node-sdk`，无需公网）。

- **2026-11-10 扫码改造**：新会话说「接入飞书」→ 引导出待接入目标 → 手机飞书扫码进 bot 单聊 → `bot_p2p_chat_entered_v1` 事件自动绑定（30 分钟时效；**1.5.39 起扫码/装 app 降级为兜底**——主路径是 `feishu_bind` 不传 chatId 自动绑定最近活跃的 chat，旧绑定直接覆盖，绑定成功后 bot 在该 chat 发对接成功消息）。
- 凭证 `feishu/config.json` 存记忆根（**不入 npm 包**）。
- **发附件需权限 `im:resource`**（后台真实标识「获取与上传图片或文件资源」，免审）——开发者后台搜 **`im:resource:upload` 为 0 条，后台不存在这个独立 scope**，真名就是 `im:resource`（详见坑 #70 / #71；速查另见 README「已知限制与飞书权限」）。
- **1.5.36 起状态不再失真**：`feishu_status` 的 `connected` 是**实时值**（接 SDK 的 `onReconnecting`/`onReconnected`/`onError`，断连/重连期间立刻变 false，并用 `getConnectionStatus()` 快照兜底对账），另给 `healthy`（在线 且 5 分钟内重连未超过 3 次）与 `warning`；`apps[]` 逐条带 `connectedAt` / `lastDisconnectAt` / `reconnectCount` / `lastError`（1.5.35 的 `inboundRouting` 入站路由回看同时保留）。

排障（配置脚本、卡片渲染、历史修复）：[飞书接入与排障](./飞书接入与排障.md)。

## 对接落到哪个会话（路由规则）

实现：`lib/feishu.js` 的 `pending-bind` + `lib/feishu-logic.js` 的 `decideUnboundChatRouting()` + `lib/weixin/accounts.js` 的 pending-bind（默认规则 1.5.32 固化，三档处理 1.5.33 落地）。

**对机器人默认落到「发起对接的那个会话」，能复用就复用、不新建**：会话 A 里说「接入飞书/微信」→ 待接入目标记的就是 A → 扫码/绑定成功后该 chat 绑回 A，聊天接着聊。只有用户明确说「新建会话」才新建；chat 从没走过对接、也没有待接入目标时程序会新建一个会话接住（**兜底，非首选**）。

**1.5.33 起**一个从没绑过的 chat 发来第一条消息时按三档自动处理：

1. 恰好 1 个活跃真人会话 → 直接接过去并告知；
2. 多个活跃 → 不绑不建，回编号列表（`1. 会话名（工作区：xxx）`）让用户选，**不替他挑"最近那个"**（会话各带上下文，投错比多问一句糟糕）；
3. 0 个 → 才新建并明说。

开关 `feishu.reuseActiveSession` 默认 `true`，设 `false` 回退 1.5.32 旧行为（一律新建）。这条同时写进 persona【飞书】【微信】两段，属行为约定而非可选配置。
