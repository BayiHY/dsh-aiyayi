# 飞书对接手册

## feishu_status 返回值怎么读（1.5.35 起，三个字段各管一摊，别混着说）

- `connected` 是**实时状态**——长连接真在线才 true，断开/重连期间就是 false
  （SDK 的连接事件实时回写，不再是「连上过一次就一直 true」的假象）。
- `healthy` 是**综合健康度**——在线的同时最近 5 分钟重连次数没超阈值才算 true。
- `warning` 有值时就是插件给的告警（比如"长连接不稳定，最近 5 分钟内重连 X 次"）。

所以：
- `connected:false` 就说"长连接现在是断的，飞书消息这会儿可能收不到"；
- `connected:true` 但 `healthy:false` 要照实补一句"在线但不太稳，最近在反复重连"；
- **别只看 connected:true 就宣布一切正常**。

逐应用细节在 `apps[]` 里：每个 appId 的
connected/connectedAt/lastDisconnectAt/reconnectCount/lastError。

新建会话第一次聊到飞书，先自查对接情况：调 feishu_status，看本会话是不是已绑定
某个飞书对话、还有哪些别的会话已绑定、长连接是否在运行。

## 没绑定怎么接入（主要从飞书侧发起、自动完成）

- 没绑定也别让用户提供 chat_id。**告诉用户在飞书里给机器人随便发一条消息，
  bot 会自动新建会话并接上**。
- 要接入指定的已有会话，就发 `绑定会话 <会话名>`。
- chat_id 由 bot 自己从收到的消息里取，用户不用填。
- `feishu_bind` 只在确实拿到了一个明确 chat_id 时才用（通常飞书侧已接入、
  想反向指定时）。
- 没绑定就照实说"还没接飞书，去飞书里给机器人发条消息就能接上"，别装作已对接。

## 新配/重配/修复飞书对接

按 feishu-setup 技能执行：本体没有 pwsh 和技能工具，派人给小伙伴，让他照技能

## "复用不新建"原则

对接默认落在「发起对接的那个会话」：他在哪个会话里说「接入飞书」，待接入目标
（pending-bind）就是那个会话，进单聊/扫码成功后 chat 绑回那里，聊天记录接着聊。
只有他明确说「新建会话」才新建。若这个 chat 从来没走过对接、也没有待接入目标，
程序会新建一个会话接住（**这是兜底、不是首选**）；这种情况照实说"给你新建了
会话 X"，别谎称接在了原会话上。

## 首次消息的三档自动处理（1.5.33 起，插件自动做的，别抢着替他绑）

一个从没绑过的 chat 发来第一条消息时，飞书插件按三档自动处理：

1. 恰好 1 个活跃真人会话 → 直接接过去，回一句"已接到你当前的会话：X"；
2. 多个活跃 → **不绑不建**，回一条编号列表（`1. 会话名（工作区：xxx）`）让他选，
   他回「2」或「绑定会话 2」就接过去——**别替他挑"最近那个"**，会话之间带着
   各自的上下文，投错比多问一句糟糕得多；
3. 0 个活跃 → 才新建，并明说"给你新建了会话 X"。

他要是问"为什么给我列表/为什么新建了"，照这三档解释。

配置项 `feishu.reuseActiveSession` 默认 `true`（三档复用生效）；
设 `false` 回到旧行为（一律新建）。
